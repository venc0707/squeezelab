# Решения проекта SqueezeLab

Источник истины по архитектуре и решениям — MASTER CHAT. Этот файл — копия состояния на конец
Phase 00 для репозитория. Рабочий чат решений не принимает: открытые пункты остаются OPEN до
ответа пользователя.

Версия состояния проекта: 1.0 (дата: 2026-11-10).

### Принято в Phase 00 (реализация; мастер-чат может пересмотреть)

| # | Решение | Причина |
|---|---|---|
| B-01 | Менеджер зависимостей: **uv** (`uv sync`, `uv.lock` в git) | Быстрая воспроизводимая установка одной командой, фиксация версий в lock-файле, управление версией Python; poetry допустим, но не нужен |
| B-02 | Python 3.11+ (`requires-python >=3.11`), `.python-version` = 3.12 | По плану проекта; 3.11 и 3.12 покрывают нужные возможности (`StrEnum`, `Self`) |
| B-03 | Раскладка `src/`, сборка hatchling, CLI `squeezelab` (argparse) | Меньше зависимостей, чем у альтернатив; импорт только установленного пакета |
| B-04 | Конфиги: pydantic v2, `extra="forbid"`, неизменяемые модели; общие параметры пресетов вынесены в служебный блок `x-common` (ключи `x-...` загрузчик отбрасывает) | Опечатка в ключе — ошибка; нет дублирования параметров |
| B-05 | Хэш конфига считается от проверенных моделей (канонический JSON), а не от текста YAML; пути в конфиге — строки | Комментарии, порядок ключей и `6`/`6.0` не меняют хэш; хэш не зависит от ОС |
| B-06 | Открытые решения хранятся как `null`; любой режим кроме `signals_only` запрещён, пока `null` остаётся в risk.yaml или exits.yaml | Решения не принимаются молча |
| B-07 | Секреты только из окружения и `.env` (вне git), `SecretStr`, маскирование в логах; `BINGX_ENV` по умолчанию `vst`; пустое значение = не задано | Безопасные умолчания |
| B-08 | Telegram: отправка только в chat_id из белого списка; токен не попадает в URL-логи и тексты ошибок (логгеры httpx переведены на WARNING) | Токен передаётся в пути URL |
| B-09 | Приватный клиент BingX: только GET и только пути из `READ_ONLY_PATHS` (баланс, права ключа); без ретраев | Торговых запросов в Phase 00 нет и не может быть случайно |
| B-10 | Pre-commit: стандартные проверки файлов, `detect-private-key`, ruff, ruff format, mypy (локальные хуки через `uv run`) | Версии инструментов берутся из lock-файла |
| B-11 | Дополнительная проверка конфига: `warmup_bars` не меньше `length` пресета на том же ТФ | %R не успевает прогреться при меньшем значении |

### D-04 и D-05: справка для решения

Решения нужны не раньше Фазы 6 (риск и размер) и Фазы 7 (исполнение); Фазы 1–5 они не блокируют.
Детали поведения биржи в обоих режимах подтвердить на VST в Фазе 7.

**Режим позиций.** В плане действует правило: вторая позиция на паре не открывается, а
противоположные сигналы на одной паре дают SKIP.

| | one-way | hedge |
|---|---|---|
| Плюсы | Одна позиция на пару, состояние и Reconciler проще; совпадает с правилами плана | Лонг и шорт независимы, направление ордеров задаётся явно (`positionSide`), нет неожиданного взаимозачёта |
| Минусы | Ошибочный встречный ордер уменьшит или развернёт позицию вместо открытия новой: нужны `reduceOnly` и проверки | Больше состояний; возможность держать обе стороны противоречит правилу SKIP, нужна явная защита в коде |
| Вывод справки | Скорее совместим с правилами плана | Нужен только если появится потребность в одновременных встречных позициях |

**Тип маржи.** План рекомендует для старта изолированную (ISOLATED).

| | isolated | cross |
|---|---|---|
| Плюсы | Ликвидация позиции не трогает остальной депозит; потери ограничены маржой позиции | Меньше шанс ликвидации отдельной позиции из-за нехватки маржи |
| Минусы | Нужно следить, чтобы цена ликвидации была заметно дальше стопа; маржа каждой позиции отдельная | Проблема одной позиции может затронуть весь депозит |

**Нужен ответ пользователя:** hedge или one-way; isolated или cross. До ответа записи остаются OPEN,
а `risk.position_mode` и `risk.margin_mode` — `null`.

## Вопросы, возникшие в Phase 00 (для мастер-чата)

Это не решения, а находки: ответов здесь нет.

1. Какой API-ключ нужен для VST (отдельный демо-ключ или ключ основного аккаунта при включённом VST):
   источники расходятся, выяснится при первом `bingx-auth-check` (см. `docs/bingx_api_notes.md`).
2. Единица измерения `exits.breakeven_buffer` не определена (план говорит «запас на комиссии»).
3. Блокировка режимов по `null` сейчас смотрит только на risk.yaml и exits.yaml, как в задании;
   `presets.*.priority` в блокировку не входит. Нужен ли он для `backtest`?
4. Хэш конфига включает app.yaml (режим, пути, уровень логов): смена уровня логов меняет хэш.
   Это следует из формулировки «все проверенные конфиги»; при желании исключить app.yaml — решение мастера.
5. Порядок ключей в строке подписи для Фазы 7 (см. заметки в `docs/bingx_api_notes.md`).

## Сервер

VPS нужен к Фазе 3 (режим «только сигналы»): 1–2 vCPU, 2–4 ГБ RAM, Ubuntu LTS, Docker, chrony
(синхронизация времени). Сейчас (Фазы 0–2) хватает локального компьютера. Docker-образы и
развёртывание в Phase 00 не делаются.
