# Runbook (Phase 00–01)

Дополняется по мере появления сервисов. Сейчас бот ничего не торгует: есть конфиги, проверки и
диагностические команды. Разработка идёт на Windows-ПК, сервер (Ubuntu Server) предназначен для
рекордеров (Phase 01); обе среды описаны ниже.

## Запуск проверок

Команды одинаковы на Windows, macOS и Linux. Вывод на русском настроен под UTF-8: на Windows
консоль переключается автоматически.

```bash
uv sync                          # окружение и зависимости
uv run pytest                    # тесты (сеть и ключи не нужны)
uv run ruff check                # линтер
uv run ruff format --check       # формат
uv run mypy                      # типы
uv run pre-commit install        # один раз: хуки перед коммитом
uv run pre-commit run --all-files
```

## Где что лежит

| Что | Где |
|---|---|
| Секреты | `.env` в корне репозитория (вне git); шаблон — `.env.example` |
| Конфиги | `config/*.yaml` (app, presets, exits, risk, symbols); каталог можно сменить `--config-dir` или `SQUEEZELAB_CONFIG_DIR` |
| Данные | Каталог из переменной `SQUEEZELAB_DATA_DIR`, иначе `paths.data_dir` в `config/app.yaml`, иначе `./data` (вне git). На сервере: `/srv/data/squeezelab` |
| Логи | `logs/` (вне git; `paths.logs_dir` в `config/app.yaml`) |
| Решения и открытые вопросы | `docs/decisions.md` |
| Факты об API BingX и их статус проверки | `docs/bingx_api_notes.md` |

## Команды

| Команда | Что делает | Сеть |
|---|---|---|
| `uv run squeezelab config check` | Проверяет конфиги, печатает режим, два хэша (`strategy_hash` и `app_hash`, sha256), каталог данных и его источник, пары рекордера, открытые решения (null) и какие секреты заданы (без значений) | нет |
| `uv run squeezelab notify-test [--dry-run]` | Отправляет тестовое сообщение (режим, оба хэша, время UTC) в чаты из белого списка; `--dry-run` только показывает текст и сообщает, задан ли прокси. Читает только секреты Telegram | Telegram (через `TELEGRAM_PROXY_URL`, если задан) |
| `uv run squeezelab bingx-smoke [--limit N] [--save-raw ФАЙЛ]` | Публичный запрос свечей BNB-USDT 15m: количество, первая и последняя метка, порядок, признак незакрытой свечи, заголовки лимитов | BingX, без ключей |
| `uv run squeezelab bingx-probe-klines [--set basic\|paging\|depth\|coverage]` | Пробные публичные запросы свечей (без ключей). `basic` (12 запросов): границы `startTime`/`endTime`, порядок, усечение, формирующаяся свеча, сырая свеча для сверки `volume`. `paging` (17 запросов): предел ответа при `limit=1440`, окна в 1000 и 1001 бар, 1m, `endTime` на границе. `depth` (около 100 запросов, около минуты): начало истории пары бисекцией для 15m, 1m, 1h, 4h, 1d и предел ответа для каждого (при пропусках в данных биржи может дать завышенное начало). `coverage` (415 запросов, около двух минут): карта наличия данных, суточные окна по 1-м и 15-м числам месяцев с 2022-01 для каждого ТФ плюс 2026-06-25; печатает таблицу `получено/ожидается` и выводы. Печатает наблюдения и выводы. Запускать на машине с прямым доступом к BingX | BingX |
| `uv run squeezelab data download [--symbol BNB-USDT] [--tf 15m --tf 1m] [--start ...] [--end ...] [--window-bars N]` | Скачивает закрытые свечи в Parquet (`{каталог данных}/candles/{пара}/{ТФ}/{ГГГГ-ММ}.parquet`); по умолчанию 15m и 1m с 2026-06-25 00:00 UTC до последней закрытой свечи. Повторный запуск докачивает, ничего не удаляет; по ошибке API сохраняет накопленное и завершается с кодом 1. Печатает число свечей, запросов, пропуски | BingX (публичный, ключи не нужны) |
| `uv run squeezelab data check [--symbol] [--tf] [--start] [--end] [--cross 1h:15m] [--no-cross] [--report-dir]` | Проверяет качество сохранённых свечей (девять проверок на ряд, см. `decisions.md` B-29), сверяет 15m с агрегатом из 1m (и другие пары через `--cross`), пишет отчёт в `{каталог данных}/reports/quality_*.md`, печатает краткий итог. Код выхода 1 при ошибках или расхождениях. Сеть и ключи не нужны | нет |
| `uv run squeezelab data sync [--symbol] [--tf] [--start] [--end]` | Докачивает новые свечи и пропуски узкими окнами; те, которых биржа так и не отдала (старше 6 часов), помечает «подтверждённо отсутствуют» и больше не запрашивает. По умолчанию пары и ТФ из `downloader` в `app.yaml` (BNB-USDT: 15m, 1m, 1h, 4h, 1d), период от первой сохранённой свечи. Код выхода 3, если остались неподтверждённые пропуски или у настроенной пары нет данных | BingX (публичный) |
| `uv run squeezelab data resample [--symbol] [--from 1m] [--to 15m] [--no-compare]` | Собирает 15m из 1m в отдельный слой `candles_resampled/` (полные корзины :00/:15/:30/:45 UTC), сверяет с нативным 15m на общем периоде, печатает вердикт («допустим», «допустим с исключениями» или «НЕ допустим», тогда код выхода 1) и пишет отчёт `resample_*.md` в `reports/`. Сеть не нужна | нет |
| `uv run squeezelab bingx-auth-check [--show-balance]` | Один подписанный запрос на чтение (баланс) в окружении `BINGX_ENV`, затем справочная проверка прав ключа. Читает только секреты BingX | BingX, ключ |

Коды выхода: 0 — успех, 1 — сбой операции (сеть, API), 2 — ошибка конфига или аргументов.

## Telegram: бот и chat_id (делает пользователь, P00-T03)

1. В Telegram открой @BotFather, команда `/newbot`, задай имя и username (оканчивается на `bot`).
   BotFather пришлёт токен вида `123456789:AA...`. Это секрет: не публикуй и не присылай в чат.
2. Создай группу (или канал) для сигналов и добавь туда бота. Для канала бот должен быть
   администратором с правом публикации.
3. Напиши в группу любое сообщение (в личном чате нажми Start у бота).
4. Узнай chat_id: открой в своём браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` (подставь токен) и найди `"chat":{"id":...}`.
   У групп число отрицательное. У супергрупп и форумов (с топиками) для API нужен идентификатор
   с префиксом `-100`, например `-1001234567890`: число из адресной строки веб-версии Telegram
   без `-100` для API не подходит. Не публикуй этот адрес и скриншоты с ним.
   Если ответ пустой, отправь в группу ещё одно сообщение и обнови страницу.
5. Впиши в `.env` (файл создаётся копированием `.env.example`):
   ```
   TELEGRAM_BOT_TOKEN=<токен>
   TELEGRAM_CHAT_IDS=<chat_id>            # несколько через запятую
   ```
6. Проверь: `uv run squeezelab notify-test --dry-run`, затем `uv run squeezelab notify-test`.
   В мастер-чат пришли вывод команды (токен он не печатает) и подтверждение, что сообщение
   пришло. Если токен всё же засветился, отзови его в @BotFather (`/revoke`) и выпусти новый.

### Группа с топиками (форум)

Клиент пока отправляет сообщения без `message_thread_id`, поэтому всё попадает в топик General.
Отправка по топикам (отчёты, ошибки, сканы и т. д.) — отдельная задача на потом, см.
`docs/decisions.md`.

## BingX: демо VST и ключ на чтение (делает пользователь, P00-T05)

1. Аккаунт BingX с включённой двухфакторной защитой.
2. Включи демо-режим VST для фьючерсов (названия пунктов меню в приложении и на сайте меняются).
3. Создай API-ключ в разделе управления API: **только чтение**, без торговли и вывода; если можно,
   привяжи к IP машины, с которой запускаешь команды. Секрет показывается один раз: сохрани сразу.
   Торговый ключ сейчас не создаём.
4. Впиши в `.env`:
   ```
   BINGX_API_KEY=<ключ>
   BINGX_API_SECRET=<секрет>
   BINGX_ENV=vst
   ```
5. Проверь:
   ```bash
   uv run squeezelab bingx-smoke --save-raw tests/fixtures/bingx_klines_real.json
   uv run squeezelab bingx-auth-check
   ```
   В мастер-чат пришли выводы обеих команд (ключ в них показан маской, секрет не показывается).
6. Если `bingx-auth-check` не проходит, прочитай причину и список проверок в выводе.
   Проверено 2026-11-13: на VST принят ключ основного аккаунта из обычного раздела API
   Management, отдельного демо-ключа нет. Значит, тот же ключ действителен и на боевом контуре:
   он должен быть только на чтение.
7. BingX блокирует доступ по региону («Доступ закрыт»), в том числе с части VPN. Запросы к
   BingX запускай без VPN.

## Linux (сервер) и ПК: одинаковая проверка

Код работает на обеих платформах без правок. Сервер: Ubuntu Server, данные на отдельном диске
`/srv/data`, перезагрузки вручную.

```bash
# сервер, один раз
git clone <адрес репозитория> squeezelab && cd squeezelab
uv sync
cp .env.example .env              # заполнить только нужное; права: chmod 600 .env

# каждая сессия (в юните systemd переменная задаётся через Environment=)
export SQUEEZELAB_DATA_DIR=/srv/data/squeezelab
uv run squeezelab config check
```

Сверка среды: в выводе `config check` на ПК и на сервере должны совпасть обе строки с хэшами
(`strategy_hash` и `app_hash`). Они не зависят от ОС и от `SQUEEZELAB_DATA_DIR`. Строка
«Каталог данных» на сервере покажет `/srv/data/squeezelab (источник: переменная
SQUEEZELAB_DATA_DIR)`, на ПК обычно `data (источник: paths.data_dir в app.yaml)`: это нормально,
различие в путях хэши не меняет. Хэши расходятся, если на машинах разные версии файлов
`config/*.yaml`: сравни `git rev-parse --short HEAD`.

`SQUEEZELAB_DATA_DIR` читается только из окружения процесса, не из `.env`. Каталог команда сама не
создаёт: его создаёт хранилище при первой записи (P01-T02).

## Проверка качества данных (P01-T03)

```bash
export SQUEEZELAB_DATA_DIR=/srv/data/squeezelab
uv run squeezelab data check          # все пары и ТФ, кросс-проверка 15m против 1m, отчёт в reports/
uv run squeezelab data sync           # если нашлись пропуски: докачка и подтверждение отсутствующих
uv run squeezelab data check          # после докачки: подтверждённые пропуски уже предупреждение
```

Что читать в выводе: строка по каждому ряду (`OK`, `OK с предупреждениями` или `ОШИБКИ: …`), строка
кросс-проверки (`расхождений нет` или `РАСХОЖДЕНИЯ в N свечах (поля)`), путь к отчёту и итог.
Подробности (примеры по каждой проверке, таблица расхождений) в markdown-отчёте. Если расхождения
есть, это не обязательно ошибка загрузки: 15m и агрегат из 1m у биржи могут считаться по-разному,
и тогда вопрос к мастеру, как ресемплить 1m в 15m для истории до августа 2026.

## Ресемпл 15m из 1m и ежедневные таймеры (P01-T03)

```bash
export SQUEEZELAB_DATA_DIR=/srv/data/squeezelab
uv run squeezelab data resample        # 15m из 1m в слой candles_resampled/, сверка, вердикт
uv run squeezelab data check           # теперь проверяет и нативные ряды, и ряды ресемпла
sudo deploy/install.sh --dry-run       # что будет установлено
sudo deploy/install.sh                 # таймеры squeezelab-sync (04:30 UTC) и squeezelab-backup (05:30 UTC)
systemctl list-timers 'squeezelab-*'
journalctl -u squeezelab-sync -n 50    # итог последней докачки
```

Вердикт ресемпла определяет только OHLC: «допустим» (совпали на всех барах) или «допустим с
исключениями» (меньше 0,1 % баров, список в отчёте). «НЕ допустим» значит остановиться и написать
мастеру. Нативный 15m BingX есть только около 100 суток, историю до него даёт ресемпл из 1m.
Читающий API (`squeezelab.data.reader.CandleReader`) отдаёт у каждой свечи `src` (`native` или
`resampled`) и по умолчанию предпочитает нативную.

Таймеры `Persistent=true`: если сервер был выключен в 04:30 UTC, пропущенная докачка и копия
запустятся сразу после загрузки (так и случилось 2026-11-26: сервер включили вечером, и обе
службы стартовали в 17:47 и 17:50). Проверка: `systemctl list-timers 'squeezelab-*'`,
`journalctl -u squeezelab-sync -n 60 --no-pager`.

Установка таймеров: нужен `uv sync` в репозитории (юнит запускает `.venv/bin/squeezelab`) и
пакет rsync; `install.sh` запускают через `sudo` (юниты работают от вашего пользователя, не от
root), повторный запуск безопасен. Копия делается `rsync -a` без `--delete`: файлы, пропавшие в
источнике, в копии остаются. Статус `failed` у `squeezelab-sync` значит код 3: остались
неподтверждённые пропуски, данные сохранены, детали в журнале.

## Прокси (Telegram) и прямое соединение (BingX)

- **BingX всегда напрямую.** Клиенты BingX игнорируют `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` и
  `NO_PROXY`. BingX блокирует часть регионов и VPN, поэтому запросы к нему не должны идти через
  прокси или VPN.
- **Telegram через явный прокси.** Если `api.telegram.org` недоступен напрямую (сервер), задай в
  `.env` адрес локального прокси, например Xray с HTTP-входом:
  ```
  TELEGRAM_PROXY_URL=http://127.0.0.1:10809
  ```
  Допустимы схемы `http` и `https`; `socks5` не поддерживается. Адрес считается секретом (в нём
  бывают логин и пароль): он не печатается и маскируется в логах. Пустое значение = без прокси.
- Проверка: `uv run squeezelab notify-test --dry-run` печатает «Прокси Telegram: задан» или
  «не задан», затем `uv run squeezelab notify-test` отправляет сообщение.
- Клиенты проекта не читают также `SSL_CERT_FILE`, `SSL_CERT_DIR` и `~/.netrc`
  (`trust_env=False`, см. `docs/decisions.md`, B-13).

## Безопасность

- `.env` не коммитится (`.gitignore`, хук `detect-private-key`). Если секрет попал в git или чат,
  отзови его и выпусти новый.
- Ключи без права вывода и торговли (до Фазы 7), привязка к IP, 2FA на аккаунте.
- Секреты не пишутся в логи: значения маскируются, URL запросов Telegram не логируются.

## Загрузка свечей BNB-USDT (P01-T02)

Порядок на сервере (данные сразу ложатся на отдельный диск):

```bash
git pull && uv sync
export SQUEEZELAB_DATA_DIR=/srv/data/squeezelab
uv run squeezelab bingx-probe-klines --set coverage   # один раз: за какие периоды у биржи есть данные
# Всё, что есть у биржи (начало раньше истории сдвигается само, с предупреждением):
uv run squeezelab data download --tf 15m --tf 1m --start 2025-01-01
uv run squeezelab data download --tf 1h --tf 4h --tf 1d --start 2022-01-01
uv run squeezelab data download --tf 15m --tf 1m --start 2025-01-01   # второй запуск: ничего нового
```

Ориентиры по объёму для BNB-USDT (карта покрытия 2026-11-21): у биржи 15m есть с 2026-08-13
(около 9,6 тыс. свечей, 10 окон), 1m с 2025-11-20 (около 527 тыс. свечей, около 530 окон, порядка
двух минут при 5 запросах в секунду), 1h с 2024-04-27, 4h с 2022-10-13, 1d с 2022-03-12. Период по
умолчанию (с 2026-06-25) годится только для 1m: для 15m до 2026-08-13 данных нет, загрузчик
сдвинет начало сам. В отчёте строки «в хранилище за период: N из N» и «пропусков нет» означают, что
всё на месте. После каждого ТФ идёт отдельный отчёт; код выхода 0, если запросы прошли, и 1 при
сбое API (накопленное сохраняется, достаточно запустить команду ещё раз). Единичные ошибки биржи
загрузчик повторяет сам (до трёх раз, паузы 2, 5, 10 секунд) и пишет число повторов в отчёте.

Если печатается «ВНИМАНИЕ: у биржи нет свечей раньше …», история пары начинается позже `--start`:
период начат с самой ранней свечи биржи (это нормально: у 15m окно хранения около 100 суток и
скользит, начало сдвигается на каждой свече).

**Докачку нужно запускать регулярно.** Биржа удаляет старые свечи 15m (окно около 9600 баров), а
в архиве они остаются. Достаточно раз в сутки, не реже раза в 90 суток:
`uv run squeezelab data download --tf 15m --tf 1m --start 2025-01-01` (и раз в неделю то же для
`--tf 1h --tf 4h --tf 1d --start 2022-01-01`). Каждый запуск тратит около 25 запросов на поиск
начала истории, остальное берёт из архива. Таймер systemd для этого ждёт решения мастера
(`decisions.md`, п. 13).

Если печатается «ВНИМАНИЕ: конец периода урезан по свече биржи», часы машины спешат относительно
биржи: проверь синхронизацию времени (на сервере `chronyc tracking`).

## Типичные проблемы

| Симптом | Что делать |
|---|---|
| `config check`: ОШИБКА с путём `lvl6.level` и т. п. | Исправить значение в `config/*.yaml` по тексту ошибки |
| `режим ... запрещён, пока открыты решения (null)` | Режимы кроме `signals_only` включаются только после закрытия решений в `risk.yaml` и `exits.yaml`; для `paper_vst` и `live` нужны ещё `presets.*.priority` |
| `notify-test`: таймаут или сетевая ошибка | Проверить сеть; `api.telegram.org` может быть недоступен напрямую: на сервере задай `TELEGRAM_PROXY_URL` и проверь, что прокси слушает порт (`ss -ltn \| grep 10809`) |
| `config check`: `TELEGRAM_PROXY_URL: ожидается адрес вида http://...` | Нужна схема `http://` или `https://`, хост и числовой порт; `socks5://` не поддерживается |
| На сервере данные ложатся не туда | Запусти `config check` и посмотри строку «Каталог данных»: если там `data`, переменная `SQUEEZELAB_DATA_DIR` не передана процессу (в systemd нужен `Environment=`) |
| `config check` на ПК и сервере печатает разные хэши | Сравни версии файлов `config/*.yaml` (`git rev-parse --short HEAD`); путь данных и `.env` на хэши не влияют |
